## 1. はじめに

### 1.1 この文書の目的
本書は、無償で提供する「タスク管理アプリ」について、**何ができて、何ができないか**、**利用にあたっての前提・注意点**を提供先の方と共有するための文書です。
内容に相違や不明点がある場合は、利用開始前にご連絡ください。

### 1.2 アプリの概要
Trello のような「かんばん方式」のタスク管理アプリです。
画面上に列(例: 未着手・進行中・完了)を並べ、タスクを書いた「カード」をドラッグ&ドロップで動かすことで、仕事の進み具合を見える化できます。

ログイン機能を持ち、利用者ごとに専用のボードを保存します。データはインターネット上のサーバーではなく、**お使いのPCの中のデータベース**に保存します。

### 1.3 導入によって期待できること
- やるべきことを一覧で把握でき、抜け漏れを防げる。
- 期限を過ぎたタスクが赤く表示され、対応漏れに気づける。
- ログインにより、同じPCを複数人で使っても、他の人のタスクは見えない。
- データはPC内のデータベースに保存され、ブラウザの操作(閲覧データの削除など)で消える心配がない(v1からの改善点)。

### 1.4 想定する利用者・利用シーン
- **利用者**: 個人、または数人程度の少人数。特別なIT知識は不要です(利用開始時のみ、後述のセットアップ作業があります)。
- **利用シーン**: 日々の作業管理、小規模なプロジェクトの進捗管理など。
- **前提**: 1台のPCの中で、利用者ごとにログインしてボードを使い分けます。**別のPCとの間でのデータ共有・同期は行いません**(2.2 参照)。

| 免責 | 本アプリの利用または利用不能によって生じた損害(データ消失を含む)について、提供者は責任を負いません |
| 利用の範囲 | 提供先での利用(個人・少人数のチーム内)を想定しています。第三者への再配布や改変は、事前にご相談ください(※) |
| サポート | 9章に記載の範囲で、可能な限り対応します(対応時期・内容の保証はありません) |

※ 利用許諾(ライセンス)の扱いは、提供前に提供者が最終決定します。

### 2.2 重要な前提
本バージョンでは、データベース(PostgreSQL)をお使いのPCの中で動かします(**インターネット上のサーバーは使いません**)。そのため、サーバーの運用費用は発生せず、無償提供のまま提供できます。一方で、次の制約があります。

- データは**そのPCの中だけ**に保存されます。他のPCからは見えません。
- 別のPCでも使いたい場合は、そのPCにも同じセットアップを行い、**別々のデータ**として利用します(データの同期・引っ越しは今回のスコープ外。10章参照)。
- ログイン機能により、**同じPCの中では**、利用者ごとにタスクが分かれます。
- PostgreSQLは、SQLiteのような単一ファイルではなく、**常時起動しておく必要があるデータベースソフト**です。セットアップの手間が、素のファイル保存方式に比べて増えます(3.2・6.2・8.2 参照)。

## 3. 成果物

### 3.1 提供するファイル一式

```
TaskManagment/
├─ backend/                … バックエンド(Java / Spring Boot)
│  ├─ pom.xml              … Maven設定(使用ライブラリの一覧)
│  └─ src/main/
│     ├─ java/...          … アプリ本体(ログイン確認・列やカードの操作・並び替え)
│     └─ resources/
│        ├─ application.properties … DB接続設定
│        ├─ db/migration/  … Flywayによるテーブル定義(マイグレーション)
│        └─ static/        … frontendのビルド成果物を配置(3.2参照)
├─ frontend/                … フロントエンド(React / Vite)
│  ├─ package.json
│  └─ src/
│     ├─ pages/            … ログイン画面・メイン画面
│     └─ components/       … 列・カード・ダイアログ等の部品
├─ SETUP.md                … セットアップ手順(初回のみ)
├─ README.md                … 概要・起動方法
└─ docs/
   ├─ requirements.md      … 本要件定義書
   ├─ screen-design.html   … 画面イメージ
   └─ diagrams.md          … 画面遷移図・データフロー・ER図(Mermaid記法)
```

- データの実体は、別途インストールする PostgreSQL の中に保存されます(ファイル1つという形では持ちません)。

### 3.2 提供方法・セットアップ
- 公開サーバーへの設置(インターネット上でのホスティング)は行いません。**アプリはお使いのPCの中だけで動作**します。
- `frontend`(React)はビルドした上で `backend` の静的リソースに同梱し、**実行するプロセスは1つ(Spring Bootのjarファイル)** にまとめます。利用者が複数のプロセスを個別に起動する必要がないようにするためです。
- 利用開始前に、1回だけセットアップ作業が必要です(詳細は SETUP.md、概要は 8.2 章)。
  - Java(JDK 21)のインストール(未導入の場合)
  - PostgreSQLのインストールと、データベースの作成
  - ファイル一式(配布するjarファイル)の配置
  - 初回起動とブラウザでのアクセス
- 以後は、配布されたjarファイルを起動して、ブラウザで `http://localhost:xxxx` を開くことで利用します。

### 3.3 ソースコード
- ソースコードは GitHub リポジトリで管理し、変更履歴はコミット履歴で確認できます。
- 提供先にはファイル一式を提供します。

### 3.4 ドキュメント
- 本書、SETUP.md、README(起動方法・機能一覧)を提供します。
- テスト仕様書・詳細な運用手順書は作成しません。

## 5. 機能要件

### 5.1 ログイン・アカウント機能

| No. | 機能 | 仕様 |
|---|---|---|
| L-1 | アカウント登録 | 初回利用時に、ユーザー名とパスワードを決めて登録する。ユーザー名は重複不可 |
| L-2 | ログイン | 登録したユーザー名・パスワードでログインする |
| L-3 | ログアウト | 画面上部からログアウトできる。ログアウト後は再度ログインが必要 |
| L-4 | データの分離 | ログインした利用者ごとに、列・カードのデータが分かれる。他の利用者のボードは見えない |
| L-5 | パスワードの扱い | パスワードは読み取れない形(ハッシュ化)でデータベースに保存する。ID・パスワードを忘れた場合の復旧手段は用意しない(9.2 参照) |

### 5.2 カラム(列)機能

| No. | 機能 | 仕様 |
|---|---|---|
| C-1 | 初期表示 | 新しいアカウントの初回ログイン時に「未着手」「進行中」「完了」の3列を自動作成する |
| C-2 | 列の追加 | 「+ 列を追加」から列名を入力して追加できる。列名は必須、1〜20文字。列数の上限は10列 |
| C-3 | 列の削除 | 列のメニューから削除できる。列内にカードがある場合は「カードも一緒に削除されます」と確認を表示し、了承した場合のみ削除する |

### 5.3 タスクカード機能

**カードが持つ情報**

| 項目 | 内容 | 入力 | 制約 |
|---|---|---|---|
| タイトル | タスク名 | 必須 | 1〜50文字 |
| 詳細説明文 | 補足情報 | 任意 | 500文字まで |
| 期限日 | 締め切り日 | 任意 | 日付形式(年/月/日)。過去の日付も入力可 |
| 重要度 | タスクの優先度 | 任意(3段階) | 「重」「中」「低」から選択。未設定も可(初期値は未設定) |
| 作成日時 | カードを作った日時 | 自動記録 | 利用者は変更不可 |

重要度は、カード上に色付きのバッジで表示する。

| 重要度 | 表示色 |
|---|---|
| 重 | 赤 |
| 中 | オレンジ |
| 低 | 黄 |
| 未設定 | バッジを表示しない |

**カードの操作**

| No. | 機能 | 仕様 |
|---|---|---|
| T-1 | 追加 | 各列の「+ タスク追加」から入力して追加する。追加したカードは列の末尾に並ぶ |
| T-2 | 編集 | カードをクリックして、タイトル・詳細説明文・期限日・重要度を変更できる |
| T-3 | 削除 | カードの削除ボタンで削除できる。削除前に確認を表示し、削除後は元に戻せない |
| T-4 | 移動・並び替え | ドラッグ&ドロップで、別の列への移動、および同じ列内での自由な並び替え(好きな位置への挿入)ができる |
| T-5 | 並び替えボタン | 各列の上部に「優先度順」「期限順」ボタンを設け、押すとその列の中のカードを並び替える。優先度順は「重→中→低→未設定」の順。期限順は期限が近い順(期限未設定は最後)。ボタンによる並び替えの後も、T-4による自由な並び替えは引き続きできる |

### 5.4 期限切れ表示

| No. | 機能 | 仕様 |
|---|---|---|
| D-1 | 期限切れの強調 | 期限日が今日より前のカードは、赤系の背景色と枠線で表示する |
| D-2 | 判定のタイミング | 画面を開いたとき・再読み込みしたとき、およびカードの追加・編集時に判定する |
| D-3 | 完了列のカード | 「完了」列にあるカードは、期限を過ぎていても強調表示しない |

### 5.5 基本的な操作の流れ

1. ローカルサーバーを起動し、ブラウザで開く
2. ログイン画面で、アカウントを登録(初回)またはログインする
3. 自分のボード(3つの列)が表示される
4. 列の「+ タスク追加」を押す → タイトル等を入力して保存 → カードが列に追加される
5. 作業が進んだら、カードを次の列へドラッグ&ドロップする
6. 期限を過ぎると、カードが赤く表示される
7. 不要になったカードは削除する
8. 使い終わったらログアウトする(複数人で1台のPCを使う場合)

## 6. 非機能要件・利用上の制約(必ずお読みください)

### 6.1 データの保存方法と、それによる制約
本アプリのデータは、**お使いのPCの中で動かすPostgreSQL**に保存されます。インターネット上のサーバーにはデータを送信しません。

| 状況 | 結果 |
|---|---|
| ブラウザの「閲覧データの削除」をした | **影響ありません**(データはブラウザではなくPostgreSQLに保存されるため) |
| 別のブラウザ(ChromeとEdgeなど)で開いた | ログインすれば同じデータが見えます(ブラウザには依存しません) |
| 別のPCで開いた | データは表示されません(そのPC専用のデータのため。共有はしません) |
| 同じPCを複数人で共有した | ログイン機能により、利用者ごとに別のボードになります。ただし、他人のパスワードを知っていればログインできてしまう点にご注意ください(6.4参照) |
| PostgreSQLのデータを削除・破損させた(誤操作、PCの故障など) | **タスクがすべて消えます**。バックアップ機能は今回のスコープ外です(10章) |
| PCを買い替えた・OSを再インストールした | 手動でPostgreSQLのデータを引っ越さない限り、データは引き継がれません。これはSQLiteの単一ファイルをコピーするより手順が多くなります |
| PostgreSQLを起動し忘れた | アプリの画面は表示されるか、または接続エラーになります。先にPostgreSQLを起動してから、本アプリを起動してください(8.2参照) |

**データ保護のためのお願い**
- 大切なタスクは、別途メモ等にも控えを残してください。
- 本バージョンには、データの自動バックアップ・復元機能はありません。

### 6.2 対応環境

| 項目 | 内容 |
|---|---|
| 実行環境 | Java(JDK 21)、PostgreSQL(いずれもセットアップ時に導入。バージョンは SETUP.md に記載) |
| 対応ブラウザ | Google Chrome、Microsoft Edge の最新版 |
| 対応端末 | Windows / Mac のPC |
| 非対応 | スマートフォン・タブレット、Internet Explorer |
| ネットワーク | インターネット接続は不要(バックエンドとブラウザ、バックエンドとPostgreSQLは、いずれもPC内だけの通信) |

### 6.3 性能・操作性
- カードが合計200件程度までは、操作の待ち時間を感じない動作を目標とします。
- 表示・操作はすべて日本語です。

### 6.4 セキュリティ・プライバシー
- ログインにより、他の利用者のボードへの誤操作は防げますが、本アプリは**社外・インターネットに公開しての利用を想定していません**。PCの外からはアクセスできない設定を前提とします。
- パスワードはハッシュ化して保存しますが、通信は暗号化しません(PC内のみの通信のため)。
- 個人情報や機密情報の入力は、ご自身の判断と責任で行ってください。

### 6.5 技術スタック・実装方針

| 区分 | 採用技術 | 補足 |
|---|---|---|
| バックエンド | Java 21(LTS)+ Spring Boot 3.x | ビルドツールは Maven |
| データベースアクセス | Spring Data JPA(Hibernate) | PostgreSQL用のJDBCドライバを使用 |
| データベース | PostgreSQL | テーブル定義は Flyway で管理 |
| 認証 | Spring Security(セッション方式)+ BCryptによるパスワードハッシュ化 | L-5の要件に対応 |
| フロントエンド | React 18(Vite でビルド) | Next.js は使用しない |
| 画面遷移 | React Router | ログイン画面・メイン画面の切り替え |
| API通信 | REST API(JSON)。ブラウザ側は標準の fetch を使用 | 追加の通信ライブラリは使用しない |

- 大掛かりなクラウド基盤や有償ミドルウェアは使用しません(無償提供のため)。
- フロントエンド(React)のビルド成果物は、バックエンド(Spring Boot)の静的リソースに同梱し、利用者が起動するプロセスを1つにまとめます(3.2参照)。

## 7. データ設計(DBテーブル定義)

PostgreSQL上に作成するテーブルです。実装では Flyway のマイグレーションファイルとして管理します。
詳細な図は [docs/diagrams.md](diagrams.md) の「3. ER図」を参照してください。概要は以下のとおりです。

### 7.1 users テーブル(利用者)

| 列名 | 型 | 説明 |
|---|---|---|
| id | 整数(主キー) | 利用者の識別子 |
| username | 文字列 | ログインに使うユーザー名(重複不可) |
| password_hash | 文字列 | ハッシュ化したパスワード |
| created_at | 日時 | 登録日時 |

### 7.2 columns テーブル(列)

| 列名 | 型 | 説明 |
|---|---|---|
| id | 整数(主キー) | 列の識別子 |
| user_id | 整数(外部キー→users.id) | どの利用者の列か |
| name | 文字列 | 列名 |
| position | 整数 | 表示順 |

### 7.3 cards テーブル(カード)

| 列名 | 型 | 説明 |
|---|---|---|
| id | 整数(主キー) | カードの識別子 |
| column_id | 整数(外部キー→columns.id) | どの列に属するか |
| title | 文字列 | タイトル |
| description | 文字列 | 詳細説明文 |
| due_date | 日付 | 期限日 |
| priority | 文字列 | 重要度(`high`=重 / `medium`=中 / `low`=低 / 未設定) |
| created_at | 日時 | 作成日時 |
| position | 整数 | 列内での表示順(自由な並び替え・並び替えボタンの結果を保持) |

### 8.2 導入・利用開始の手順(概要)
詳細な手順は SETUP.md に記載します。概要は次のとおりです。

1. (未導入の場合)Java(JDK 21)をインストールする。
2. (未導入の場合)PostgreSQLをインストールし、本アプリ用のデータベースを作成する。
3. 提供されたファイル一式(jarファイル)を、PC上の任意のフォルダに保存する。
4. 初回のみ、テーブルを作成する(アプリの初回起動時に自動で作成されます)。
5. PostgreSQLを起動する(PCの起動時に自動で立ち上がる設定にすることもできます)。
6. 配布されたjarファイルを起動する(バックエンドとフロントエンドが1つにまとまっています)。
7. ブラウザで指定のアドレス(`http://localhost:xxxx`)を開く。
8. ログイン画面が表示されたら、アカウントを登録してログインする。
9. 次回以降は、手順5・6・7・8のみで利用できます。

|---|---|
| データの復旧 | PostgreSQLのデータの削除・破損時は対応できません(6.1参照) |
| パスワードを忘れた場合 | 復旧手段がないため、提供者に連絡し、アカウントの削除・再作成で対応します(既存のタスクは失われます) |
| セットアップの支援 | Java・PostgreSQLのインストールなど、初回セットアップで分からない点があれば、9.1の窓口にご連絡ください |

---

## 10. 対象外の事項と今後の拡張候補

### 10.1 今回は対応しないこと

| 対象外の事項 | 理由・影響 |
|---|---|
| インターネット上での公開・複数PC間でのデータ共有 | サーバーの運用(費用・セキュリティ対策)が必要になるため。将来対応する場合は、6.5の構成から見直しが必要 |
| データの自動バックアップ・復元 | 今回は最小構成を優先するため。PostgreSQLの機能(pg_dump等)を使った手動バックアップは可能です |
| パスワードを忘れた場合の自動復旧(メール再設定等) | メール送信などの外部連携が必要になるため |
| スマートフォン向けレイアウト | PC利用を前提としているため |
| 列そのものの並び替え(列の表示順の変更) | カードの並び替え(T-4・T-5)を優先するため。列の順序は追加した順に固定 |

### 10.2 今後の拡張候補(実施を約束するものではありません)
- データのバックアップ・復元(書き出し・読み込み機能)
- 複数PC間でのデータ同期、またはインターネット経由での利用(サーバー化)
- パスワード再設定機能
- カードにラベル(色分けタグ)を追加
- 検索・フィルター機能
