## Q4. HTTPとは

### 回答

## Q5. HTTPとHTTPSの違い
HTTPとHTTPSの違いは何ですか？

なぜ現在のWebサイトはほぼすべてHTTPSを使用していますか？

### 回答
HTTPSは、HTTPの通信を 「TLSで暗号化」したもの。盗み見(盗聴)・改ざん・なりすましを防ぐ。
ほぼ全サイトがHTTPSなのは、パスワードや個人情報が通信経路で読まれるのを防ぐため。ブラウザも非HTTPSに警告を出す。

### 自分の理解
通信暗号なし（HTTP）・あり（HTTPS）の違い。
セキュリティ対策の為。

## Q7. HTTPメソッド
このアプリのAPIでは以下を使っています。

- GET
- POST
- PUT
- DELETE
- PATCH

これらの「HTTPメソッド」とは何ですか？

日常生活の例えで、それぞれの違いを説明してください。

### 回答
リクエストの「種類(何をしたいか)」を表す。図書館の例:

| DELETE | 削除 | 本を「廃棄する」 |

### 自分の理解
HTTPのルール（約束事）の中で決められたリクエストの種類。

## Q15. データの流れ
ユーザーが「新しいタスクを作成」ボタンを押してから、

- データベースに保存される
- 画面に反映される

### 回答

5. Reactが受け取り、state を更新 → 画面に新しいカードが表示される

1,入力して保存
2,バックエンドが受け取り・チェックする
3,データーベースへ保存

# 第3章 データベースの基礎

## Q21. データベースとは
データベースとは何ですか？

ExcelやCSVで保存する方法と比べて何が優れていますか？

### 回答
データを「整理して保存し、検索・更新を安全に行う仕組み」。
Excel/CSVより優れる点は、複数人が「同時に」使っても壊れない。
大量データでも「高速に検索」できる。
「制約(必須・重複禁止・参照整合性)」で不正データを防げる。
トランザクションで途中失敗を巻き戻せる。
権限管理ができる。

### 自分の理解
大量のデータを決まった形式で整理して保存し、必要なデータを素早く取り出せるようにした仕組みである。
読み書きや検索する速度が圧倒的に早く、複数の同時アクセスが可能。
また、データの形式を固定出来るため、一貫性を保つことが出来る。

## Q25. データの制約

- `DEFAULT 'medium'`

が設定されています。

### 回答

### 自分の理解

`DEFAULT 'medium'`は、値を指定せずに保存した時に自動で入る初期値である。

## Q27. トランザクション
トランザクションとは何ですか？

タスクを別カラムへドラッグ移動する操作で、なぜ重要ですか？

### 回答
複数の処理を「全部成功」か「全部なかったこと」のどちらかにする仕組み。

　移動先の並び順を振り直す。
　移動元の並び順を振り直す、の「複数の更新」が起きる。途中で失敗したときに片方だけ反映されるとカードの順序が壊れる。
　まとめて確定、失敗なら巻き戻しにしている。

### 自分の理解

## Q29. バージョン管理(Git)
Gitなどのバージョン管理システムとは何ですか？

なぜ必要ですか？

使わないとどんな問題が起きますか？

### 回答
ファイルの「変更履歴を記録し、いつでも過去に戻せる」仕組み。誰がいつ何を変えたかも残る。
「最終版_本当の最終.zip」が増え、上書きで他人の変更が消える、不具合の原因の変更が特定できない、元に戻せない。

### 自分の理解
変更履歴を記録し、過去の状態へ戻したり、複数人の変更を一つにまとめたりする仕組み。
履歴が残る、並行して作業ができる、変更の意図が残るができるから。
最新のファイルが増えてどれが正しいかわからなくなる、同時に編集した人の変更が上書きで消える、
変更更新履歴が分からない、PCが壊れたらすべて失う。

## Q30. ブランチとPull Request
- ブランチとは何ですか？
- Pull Request の目的は何ですか？
- なぜ全員が main に直接変更しないのですか？

### 回答
「ブランチ」は、本流(master)から分かれた「作業用の枝」。本流に影響せず安全に試せる。
「Pull Request(PR)」は、「この枝を本流に取り込んでください」という依頼。
直接 master を変更しない理由として、未確認の変更で「本流を壊さない」ため、変更の履歴と理由を残すため。

### 自分の理解
master への直接pushは禁止し、Issue → ブランチ → PR で進める。

## Q31. コミットメッセージの重要性
例：

`feat: ログイン機能を追加`

良いコミットメッセージを書くことがなぜ重要ですか？

### 回答
変更の「何を・なぜ」を後から分かるようにするため。
履歴から目的の変更を探せる、不具合の原因調査が楽になる。
レビューする人が内容を把握しやすい。

### 自分の理解
なぜ変更したのか、何を変更したのかがわかることが必要であるためコミットメッセージは重要。
